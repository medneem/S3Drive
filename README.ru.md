**S3Drive** — открытая портативная программа для Windows 10/11 x64, которая подключает S3-совместимое хранилище как диск Windows через [rclone](https://rclone.org/) и [WinFsp](https://winfsp.dev/). Интерфейс написан на Python 3.13 и PySide6.

Документация актуализирована для **v1.5.6**. [Последний опубликованный релиз](https://github.com/medneem/S3Drive/releases/latest) · [Скачать v1.5.6](https://github.com/medneem/S3Drive/releases/tag/v1.5.6).

## Возможности

- Несколько профилей S3: название, Endpoint, Access Key, Secret Key, регион, Path-Style, бакет и буква диска. Поддерживаются HTTP(S)-совместимые серверы, включая QNAP и MinIO.
- Необязательное имя бакета: пустое поле подключает корень учётной записи S3, где доступные бакеты отображаются как папки (нужны права `ListBuckets` / `s3:ListAllMyBuckets`).
- Сетевой диск WinFsp с уникальным UNC-путём и понятным именем из профиля. В Проводнике не требуется показывать служебный идентификатор сетевого ресурса.
- Подключение в обычном пользовательском режиме, в фоне после закрытия окна либо как автоматически запускаемая служба Windows.
- Кэш записи VFS (`writes`), безопасная остановка с проверкой незавершённых отправок и отдельная команда очистки кэша.
- Окно прогресса **отправки на S3**: ожидающие и активные файлы, объём, скорость, процент и оставшееся время. Для скачивания используется штатный интерфейс Проводника; монитор S3Drive работает, пока открыта программа.
- Создание ярлыка, открытие диска после подключения, русский и английский интерфейс. По умолчанию используется английский; язык можно изменить в **Settings / Настройки**.
- Защищённое Windows DPAPI хранение S3-ключей в переносимом `config.json`.
- Только одно окно S3Drive в пользовательской сессии Windows: повторный запуск активирует уже открытое окно. Значка в трее нет.
- Проверка новых стабильных выпусков и обновление по кнопке с контролем SHA-256.

## Установка и первое подключение

1. Скачайте [последний ZIP для Windows x64](https://github.com/medneem/S3Drive/releases/latest) и **полностью распакуйте** его в папку с правами записи. Не запускайте приложение непосредственно из ZIP.
2. Запустите `S3Drive.exe` **от обычного пользователя**, без постоянных прав администратора.
3. Если WinFsp отсутствует, S3Drive предложит установить драйвер из прилагаемого `winfsp-2.2.26215.msi`. Для установки MSI потребуется UAC; после неё запустите S3Drive повторно.
4. Создайте профиль: укажите адрес S3 (`http://...` или `https://...`), ключи, букву диска и при необходимости конкретный бакет. Для QNAP S3 обычно требуется **Path-Style**. HTTP используйте только в доверенной сети.
5. Выберите при необходимости ярлык, открытие после подключения или режим службы. Нажмите **Сохранить**, затем **Подключить**.

`rclone.exe` (проверяемая сборка **1.76.0**) и установщик WinFsp уже входят в архив. Отдельно устанавливать rclone не нужно. Подробная первоначальная настройка: [README_SETUP_RU.txt](README_SETUP_RU.txt).

## Режимы подключения

| Режим | После закрытия S3Drive | После перезагрузки Windows | Повышение прав |
| --- | --- | --- | --- |
| Обычный пользовательский | Диск отключается при штатном закрытии | Нет | Не требуется |
| Оставлять диск подключённым | rclone продолжает работать под текущим пользователем | Не восстанавливается автоматически | Не требуется |
| Служба Windows | Диск остаётся доступным в Проводнике | Служба стартует автоматически | UAC при установке и административных изменениях |

**Служба Windows.** Включите «Запускать как службу Windows», сохраните профиль и нажмите «Подключить». При первоначальной настройке `S3DriveAdmin.exe` с подтверждением UAC создаёт службу профиля под `LocalSystem` и защищённый компонент `S3DriveControl`. После регистрации владельца обычные **Подключить** и **Остановить службу и диск** работают без повторного UAC: S3DriveControl проверяет SID пользователя и разрешает только запуск/остановку его зарегистрированной службы. Изменение параметров, удаление службы и очистка защищённого кэша всё ещё требуют UAC. При переходе со старой установки возможна однократная регистрация существующей службы.

**Защита служебных файлов.** Ключи S3, пароль локального API и копия rclone размещаются в ограниченном каталоге `%ProgramData%\S3Drive`. Начиная с v1.5.6 новая версия служебного rclone получает отдельное имя `rclone-<хеш>.exe`: предыдущий исполняемый файл не перезаписывается, даже если Windows удерживает его после остановки. Аналогичный механизм используется для `S3DriveControl`. Само обновление приложения **не останавливает подключённые службы** и не меняет их параметры; для применения нового rclone и параметров монтирования безопасно остановите и заново подключите службу из S3Drive.

**Обратите внимание:** служебный диск может быть доступен другим локальным пользователям Windows. Для файлов на нём используется WinFsp `FileSecurity=D:P(A;;FA;;;WD)` (полный доступ группе Everyone); дополнительно действуют права, заданные S3-сервером. Не используйте этот режим для бакетов, которые должны быть изолированы от других пользователей компьютера. Не останавливайте службу через `services.msc` или `sc.exe`: они обходят проверку очереди VFS.

**Фоновый пользовательский режим.** Если выбрано «Оставлять диск подключённым после закрытия программы», rclone остаётся работать в текущей Windows-сессии, а S3Drive при следующем запуске может восстановить управление им через защищённый локальный API. После перезагрузки автоматического подключения нет. Пароль API в `%LOCALAPPDATA%\S3Drive\background.json` защищён DPAPI.

## Настройки, названия дисков и безопасность данных

Единственный источник профилей и настроек — `config.json` рядом с `S3Drive.exe`. Он хранит язык (`en` или `ru`), параметр проверки обновлений при запуске и профили с DPAPI-зашифрованными ключами. При отсутствии файла создаётся пустая конфигурация. Прежний `%LOCALAPPDATA%\S3Drive\profiles.json` больше не используется и удаляется при загрузке. Не публикуйте `config.json`: DPAPI обычно привязан к учётной записи/установке Windows, поэтому перенос файла на другой ПК не гарантирует расшифровку ключей.

Для видимого имени диска используется заданное в профиле название, а не хеш UNC-ресурса. S3Drive применяет метку для Проводника через пользовательский раздел `Explorer\MountPoints2`, а для WinFsp — также через параметры тома. Проводник может кэшировать старое имя до обновления окна. Уже установленную службу после изменения настроек следует безопасно переподключить.

S3 — **объектное хранилище, не NTFS**. Переименование может выполняться как копирование с удалением, а конкурентные изменения другим клиентом не являются атомарными. В корне учётной записи папки первого уровня — **настоящие бакеты**: удаление такой папки при наличии прав способно удалить бакет.

Для работы с каталогами включены `--s3-directory-markers` и `--dir-cache-time 0s`. Это уменьшает риск отображения устаревших списков объектов при удалении, но увеличивает число запросов LIST и **не гарантирует** согласованность с одновременными изменениями на сервере.

Для пользовательских подключений и служб используются `--vfs-cache-mode writes` и `--vfs-write-back 0s`. Перед остановкой S3Drive проверяет очередь и ошибки отправки. При незавершённых записях остановка блокируется, чтобы не оставить данные только в локальном кэше. **Не останавливайте rclone принудительно и не удаляйте VFS-кэш вручную.** «Очистить кэш» имеет дополнительную проверку и запрещена для остановленного/аварийно завершившегося подключения. Перед важным удалением или отключением проверьте результат и данные непосредственно на S3.

Не храните на S3-монтировании активные базы данных, рабочие Git-репозитории и файлы, одновременно изменяемые несколькими пользователями.

## Обновления

Стабильные версии S3Drive по умолчанию проверяют GitHub Releases при запуске. В **Настройках** можно выключить «Проверять новую версию при запуске» либо выполнить проверку вручную. Сборки `-dev.N` автоматическую проверку релизов не выполняют. При недоступности GitHub API используется официальный сайт Releases и манифест `S3Drive-update.json`.

Ничего не скачивается до нажатия **Обновить**. S3Drive проверяет размер, SHA-256, состав ZIP и `VERSION.txt`. Отдельный `S3DriveUpdater.exe` ожидает завершения GUI, заменяет только программные файлы и при ошибке пытается вернуть предыдущие. `config.json`, существующие службы, их копии rclone и VFS-кэши сохраняются. Для активного пользовательского фонового диска обновление откладывается до безопасного отключения. Старые выпуски без `S3DriveUpdater.exe` необходимо обновлять ручной распаковкой полного ZIP с сохранением `config.json`.

## Разработка и проверка

- Python **3.13**, PySide6 **6.12.0**, pywin32 **312**; для сборки используются PyInstaller (GUI и обновлятор) и Nuitka (административный помощник и служба управления).
- Сборка портативного ZIP — GitHub Actions [Build Windows](https://github.com/medneem/S3Drive/actions/workflows/build-windows.yml), с **трёхкратным запуском набора unittest**, проверкой Windows EXE и установкой/проверкой `S3DriveControl` через SCM.
- [S3 deletion E2E](https://github.com/medneem/S3Drive/actions/workflows/s3-deletion-e2e.yml) проверяет реальные монтирования WinFsp и операции удаления на **изолированном тестовом Moto S3**. Это не тест на реальном QNAP. Технические подробности: [docs/S3-DELETE-REPRO.md](docs/S3-DELETE-REPRO.md).

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-build.txt
python -m pip install -r requirements-admin-build.txt
python -m unittest discover -s tests -v
```

Обычный push в `main` **не создаёт тег или релиз**. Публикация выполняется только по явному решению владельца через ручной запуск workflow `Build Windows` с параметром `release_version` (SemVer без `v`). История выпусков — в [GitHub Releases](https://github.com/medneem/S3Drive/releases), история расследований — в [docs/](docs/).

## Антивирусы и доверие к сборке

`S3DriveAdmin.exe` выполняет административные операции с Windows SCM, поэтому поведенческие антивирусы могут сообщать о `PDM:Trojan.Win32.Generic`; отдельно бывают обнаружения официального `rclone.exe`. **Ни успешный CI, ни опубликованный SHA-256 сами по себе не доказывают ложное срабатывание.** Не отключайте защиту и не восстанавливайте подозрительные файлы без проверки. Сверьте архив с официальным релизом и сохраните событие обнаружения; при необходимости обратитесь в [Kaspersky OpenTIP](https://opentip.kaspersky.com/) или к производителю антивируса. Не передавайте `config.json`, пароли и S3-ключи. Собственные исполняемые файлы пока не подписаны сертификатом издателя.
