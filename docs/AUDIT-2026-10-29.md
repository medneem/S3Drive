# S3Drive: аудит от 2026-10-29

## Объём проверки

Проверены исходные модули приложения (GUI, профили, шифрование, S3/rclone,
управление пользователем и Windows Service), тесты, GitHub Actions,
поставляемые зависимости и документация. Это **анализ исходного кода** плюс
проверки в GitHub Actions на Windows; не независимое тестирование на настоящем
NAS/QNAP и не формальный пентест.

## Проход 1: корректность Windows и S3

- **Метка тома:** убран искусственный префикс \`S3Drive - \`. Драйвер WinFsp
  использует ограниченный буфер метки; короткое название в Проводнике не
  доказывает обрезание в самом драйвере. Для отображения полного Unicode-имени
  добавлен документированный Microsoft системный параметр
  \`HKLM\Software\Microsoft\Windows\CurrentVersion\Explorer\DriveIcons\<LETTER>\DefaultLabel\`.
  Предыдущая метка сохраняется и восстанавливается при удалении службы.
  Добавлены обновление Shell и чтение реальной метки \`GetVolumeInformationW\`.
  Ширина плитки Проводника остаётся под управлением самой Windows.
- **Права на удаление:** исправлена серьёзная ошибка — литералы \`\\n\` в
  исходнике превращали весь параметр WinFsp \`-o FileSecurity=...\` в комментарий.
  Теперь \`-o\` действительно передаётся процессу rclone. Добавлен
  регрессионный тест точной команды.
- **Корень S3:** пустое имя бакета монтирует \`s3drive_mount:\`; для просмотра
  списка бакетов требуются соответствующие разрешения S3.
- **Отключение:** перед остановкой проверяются \`vfs/stats\`,
  \`uploadsQueued\`, \`uploadsInProgress\`, \`erroredFiles\`. При ошибке
  получения статуса отключение блокируется.

## Проход 2: служба и безопасность

- **Service Control Manager:** отдельный \`S3DriveAdmin.exe\` требует UAC.
  Служба LocalSystem обеспечивает доступность тома в Проводнике.
- **Обновление rclone:** прежний общий \`ProgramData\S3Drive\bin\rclone.exe\`
  копировался только один раз и оставался устаревшим после обновления. Теперь
  при остановленной службе исполняемый файл обновляется **отдельно для каждого
  профиля**, в защищённом каталоге, без перезаписи исполняемого файла другой
  работающей службы.
- **Реестр диска:** прежняя метка восстанавливается при удалении службы.
  Если SCM не смог установить/запустить службу, применяется откат метки.
  Изменение буквы диска запрещается до удаления ранее установленной службы.
- **Файлы конфигурации:** ключи обычных профилей защищены Windows DPAPI;
  для LocalSystem отдельный rclone.conf лежит в защищённом каталоге
  \`ProgramData\S3Drive\services\...\`, доступном SYSTEM/Administrators.
- **Права монтирования:** \`FileSecurity=D:P(A;;FA;;;WD)\` предоставляет
  полный доступ **всем локальным пользователям** (SID Everyone); так было
  запроектировано для работы глобальной службы, но это требует оценки
  безопасности. Не использовать с конфиденциальными данными на общих ПК.
- **GUI:** Access Key также скрыт в поле ввода; ранее отображался открыто.
- **Валидация:** запрещены управляющие символы в имени профиля и смена
  буквы уже установленной службы.

## Проход 3: тесты и выпуск

GitHub Actions на \`windows-latest\` запускает \`compileall\` и
**полный набор \`unittest discover -s tests -v\` три раза независимо**
перед сборкой EXE. Затем проверяется создание \`S3Drive.exe\` и
\`S3DriveAdmin.exe\`, SHA256 загруженных rclone/WinFsp и состав ZIP.
Релиз публикуется только после успешного выполнения предыдущих шагов.

Исправлены тестовые проверки, которые ранее оказались частью комментария
из-за ошибочно вставленных \`\\n\`. Добавлены проверки команды WinFsp,
полного русского имени в реестре и отката, изоляции EXE служб,
поведения при пустом бакете и валидации профилей.

## Ограничения и обязательная ручная проверка Windows/QNAP

1. Проверить \`S:\` в Проводнике после остановки/повторного запуска службы;
   сравнить системную метку тома и название плитки Explorer.
2. Создать, прочитать, переименовать и удалить **тестовый** файл и папку.
3. Убедиться, что все записи дошли до S3 до остановки службы.
4. Проверить запуск службы после перезагрузки Windows.
5. Проверить права доступа к монтированию других локальных пользователей.
6. Проверить создание/удаление службы без ошибочных UAC-прав и корректное
   восстановление прежней метки диска.
7. Проверить запрет подключения S3-root при отсутствии ListBuckets и
   обычное подключение бакета при наличии разрешений.

**Важно:** три успешных прохода юнит-тестов не эквивалентны трём реальным
монтированиям на пользовательском ПК. Без WinFsp/Проводника/QNAP это нельзя
честно объявить подтверждённым.
